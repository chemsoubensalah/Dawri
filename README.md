# دوري — الطابور الإلكتروني

> خذ رقمك من هاتفك، وتعال حين يقترب دورك.

في الجزائر يذهب المريض إلى الطبيب على السادسة صباحاً ليأخذ رقماً، ثمّ ينتظر ساعات في القاعة. «دوري» يحلّ هذا:
الزبون يمسح رمز QR على الباب، فيأخذ رقماً، ويرى على هاتفه (بلا تثبيت أيّ تطبيق) «أمامك 7 أشخاص — دورك بعد نحو 50 دقيقة»، وتصله رسالة «تعال الآن» قبل دوره.

---

## ما الموجود في هذه النسخة (MVP)

| الجزء | الرابط | ماذا يفعل |
|---|---|---|
| صفحة المحلّ | `/s/<الرابط>` | أخذ رقم بالاسم والهاتف ورمز تحقّق، الرقم الحالي، عدد المنتظرين |
| تذكرة الزبون | `/t/<المعرّف>` | رقمي، كم أمامي، الوقت المتوقَّع، «هل ما زلت قادماً؟»، «تعال الآن»، تتحدّث وحدها |
| شاشة السكرتيرة | `/staff/<الرابط>` | زرّ «التالي»، «لم يحضر — التالي»، إضافة شخص يدوياً، فتح/غلق الطابور، الموافقات، إحصاءات |
| ملصق الباب | `/staff/<الرابط>/qr` | ملصق QR للطباعة بالعربية والفرنسية |
| شاشة القاعة | `/d/<الرابط>` | الرقم الحالي والتالي بخطّ كبير (لتلفاز أو هاتف قديم) — بلا أسماء |
| الإعدادات | `/staff/<الرابط>/settings` | ساعات العمل، العتبات، تغيير الرمز |

### قواعد الغياب — «الغائب لا يوقف الطابور أبداً»

1. **سؤال التأكيد:** حين يبقى 5 أمامه يُسأل «هل ما زلت قادماً؟ نعم / ألغِ». بلا ردّ خلال 10 دقائق ← يُؤجَّل دوره (يُتخطّى). حين يؤكّد لاحقاً أو يصل يستعيد مكانه برقمه الأصلي.
2. **زرّ «وصلت»:** يمسح QR الباب حين يصل (الملصق يحمل رمز باب سرّياً)، فتظهر عند السكرتيرة شارة «في القاعة».
3. **التخطّي التلقائي:** نودي ولم يؤكّد وصوله خلال 5 دقائق ← يمرّ الدور للتالي وتصبح تذكرته «مؤجَّلة». إن وصل خلال 15 دقيقة يدخل بعد الزبون الحالي مباشرة، وبعدها تنتهي. (لا يُطبَّق على من أضافته السكرتيرة ولا على من سجّل وصوله.)
4. **زرّ «لم يحضر — التالي»** للسكرتيرة.
5. **عدّاد غياب لكلّ رقم هاتف:** بعد غيابين (قابل للتغيير) تحتاج تذكرته موافقة السكرتيرة. السجلّ يُمحى بعد شهرين.
6. **ضدّ التلاعب:** تذكرة واحدة لكلّ رقم هاتف في اليوم لكلّ محلّ (محميّة بقيد في قاعدة البيانات)، ورمز تحقّق SMS من 6 أرقام (5 محاولات، 3 رموز كلّ نصف ساعة)، وتذاكر فقط في ساعات العمل وحين يكون الطابور مفتوحاً.

**الوقت المتوقَّع** = ما بقي من مدّة الزبون الحالي + (عدد من أمامك − 1) × متوسّط مدّة الزبون اليوم. في بداية اليوم نمزج بالمدّة الافتراضية (10 دقائق) حتى لا يقفز التقدير.

**من أخذ رقمه على السادسة صباحاً** لا يُزعَج قبل أن يبدأ الطبيب: التنبيهات تبدأ مع أوّل نداء في اليوم.

### قواعد عامّة
- **لا معلومات طبّية أبداً:** اسم ورقم هاتف فقط.
- **العربية (من اليمين لليسار) والفرنسية:** زرّ تبديل في كلّ صفحة.
- **هواتف رخيصة و3G ضعيفة:** بلا خطوط خارجية، بلا صور، صفحات خفيفة، تحديث كلّ 5–10 ثوانٍ يتوقّف حين تكون الصفحة مخفيّة، وحماية من الضغط المزدوج على «التالي».
- **بلا تثبيت (PWA):** صفحة ويب عادية، ويمكن «إضافتها إلى الشاشة الرئيسية» اختيارياً.
- **الاشتراك:** مجّاني أوّل شهرين تلقائياً (`trial_ends_at`). بعد انتهائه لا تُقبل أرقام جديدة عبر الإنترنت.

## التشغيل على جهازك (دقيقتان، بلا أيّ إعداد)

تحتاج Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

ثمّ افتح:
- http://localhost:3000/s/demo — صفحة الزبون (رمز التحقّق يظهر على الشاشة في وضع التجربة)
- http://localhost:3000/staff/demo — شاشة السكرتيرة، **الرمز: 1234**
- http://localhost:3000/s/demo?c=door-demo — كأنّك مسحت رمز الباب (لتجربة «وصلت»)

بدون `DATABASE_URL` يستعمل التطبيق **Postgres مضمَّناً** (PGlite) في المجلّد `.pglite/`، ويُنشئ المحلّ التجريبي تلقائياً. احذف المجلّد لتبدأ من الصفر.

> نصيحة: افتح صفحة الزبون في نافذة خاصّة (أو على هاتفك عبر نفس الشبكة) وشاشة السكرتيرة في نافذة أخرى، واضغط «التالي» لترى التحديث الحيّ.

## الاختبارات

```bash
npm test            # 42 اختباراً: منطق الطابور + سيناريوهات كاملة على Postgres مضمَّن
npm run test:e2e    # متصفّح حقيقي: زبونان + سكرتيرة، نداء، غياب، عودة، فرنسية، QR
npm run typecheck
```

نفس اختبارات الخدمة تعمل على Postgres حقيقي (مسار الإنتاج عبر مكتبة `pg`):

```bash
TEST_DATABASE_URL=postgres://user:pass@localhost:5432/test npx vitest run tests/service.test.ts
```

> ⚠️ هذا الأمر يمسح كلّ الجداول في قاعدة الاختبار. لا تضعه على قاعدة الإنتاج.

ما تغطّيه الاختبارات: الأرقام المتسلسلة، الوقت المتوقَّع، سؤال التأكيد والتأجيل بعد 10 دقائق، التخطّي التلقائي، العودة خلال 15 دقيقة، انتهاء التذكرة وتسجيل الغياب، الموافقة بعد غيابين، محو السجلّ بعد شهرين، تذكرة واحدة لكلّ هاتف، حدود رموز التحقّق، ساعات العمل، غلق الطابور، انتهاء الاشتراك، قفل الدخول بعد 5 محاولات، **طلبات متزامنة** (8 أشخاص في نفس اللحظة ← أرقام فريدة؛ 4 ضغطات على «التالي» ← تنجح واحدة).

يعمل كلّ هذا تلقائياً على GitHub Actions مع كلّ دفع (`.github/workflows/ci.yml`).

## النشر (Supabase + Vercel)

### 1) Supabase — قاعدة البيانات
1. أنشئ مشروعاً على [supabase.com](https://supabase.com) (اختر منطقة أوروبا، مثل Frankfurt، فهي الأقرب للجزائر).
2. **أنشئ الجداول** بإحدى طريقتين:
   - افتح **SQL Editor** والصق محتوى `db/migrations/001_init.sql` ثمّ Run؛ أو
   - من جهازك: `DATABASE_URL="..." npm run db:migrate`
3. انسخ رابط الاتّصال: **Project Settings ← Database ← Connection string ← Transaction pooler** (المنفذ `6543`). استبدل `[YOUR-PASSWORD]` بكلمة سرّ قاعدة البيانات.

> لماذا اتّصال Postgres مباشر وليس `supabase-js`؟ لأنّ كلّ ضغطة على «التالي» تجري في **معاملة واحدة تقفل طابور ذلك اليوم** (`SELECT … FOR UPDATE`)، فلا يتعارض طلبان ولا يُعطى رقمان متطابقان. الجداول محميّة بـ RLS بلا سياسات، فمفتاح `anon` العامّ لا يقرأ منها شيئاً؛ كلّ الوصول يمرّ عبر الخادم.

### 2) Vercel — الموقع
1. ارفع المستودع على GitHub ثمّ **Add New Project** في [vercel.com](https://vercel.com) واختره (Next.js يُكتشف تلقائياً).
2. أضف متغيّرات البيئة (انظر `.env.example`):

| المتغيّر | القيمة |
|---|---|
| `DATABASE_URL` | رابط Transaction pooler من Supabase |
| `SESSION_SECRET` | `openssl rand -base64 32` |
| `NEXT_PUBLIC_APP_URL` | رابط موقعك، مثل `https://dawri.vercel.app` |
| `SMS_PROVIDER` | `twilio` أو `webhook` (انظر أدناه) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` و `VAPID_PRIVATE_KEY` | من `npm run vapid` |
| `VAPID_SUBJECT` | `mailto:بريدك` |
| `CRON_SECRET` | أيّ نصّ عشوائي طويل |
| `SIGNUP_CODE` | (اختياري) كي لا يُنشئ أيّ أحد محلّاً |

3. **Deploy**. ثمّ افتح `/new` لإنشاء أوّل محلّ، واطبع الملصق من شاشة السكرتيرة.

**المنطقة:** `vercel.json` يشغّل الخادم في فرانكفورت (`fra1`)، قرب قاعدة Supabase وقرب الجزائر. إن اخترت منطقة أخرى لـ Supabase فغيّرها هنا أيضاً.

**المهمّة اليومية:** `vercel.json` يستدعي `/api/cron` كلّ ليلة (02:00 UTC) ليُغلق تذاكر الأمس ويمحو سجلّ الغياب الأقدم من شهرين. (المهل القصيرة — 10 و15 و5 دقائق — لا تحتاج cron: تُطبَّق مع كلّ تحديث لشاشة السكرتيرة أو صفحة الزبون.)

### 3) رسائل SMS (رمز التحقّق)
- **Twilio** (يعمل مع الأرقام الجزائرية): `SMS_PROVIDER=twilio` مع `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_FROM`.
- **بوّابة جزائرية أو أيّ خدمة أخرى:** `SMS_PROVIDER=webhook` و`SMS_WEBHOOK_URL`. يرسل الخادم `POST` بصيغة `{"to":"+213…","text":"…"}` (مع `Authorization: Bearer SMS_WEBHOOK_TOKEN` إن وُضع). اكتب وسيطاً صغيراً يحوّلها إلى صيغة مزوّدك.
- **للتجربة الأولى فقط:** `PHONE_VERIFICATION=off` يلغي رمز التحقّق (يُضعف الحماية من التلاعب).
- `SMS_NOTIFICATIONS=1` يرسل أيضاً «تعال الآن» و«دورك الآن» برسالة SMS (مفيد لمن لا يفتح الصفحة، لكن له كلفة).

### 4) تنبيهات الهاتف (Web Push)
```bash
npm run vapid   # يطبع المفتاحين العامّ والخاصّ
```
- **أندرويد (كروم):** تعمل مباشرة بعد ضغط «فعّل التنبيهات»، بلا تثبيت.
- **آيفون:** تحتاج iOS 16.4+ و«إضافة إلى الشاشة الرئيسية». بدونها تبقى الصفحة المفتوحة تُصدر صوتاً واهتزازاً وتتحدّث وحدها.

### 5) الاشتراك
الفترة المجّانية (60 يوماً) تُضبط تلقائياً عند إنشاء المحلّ. الدفع غير مؤتمت بعد؛ بعد استلام الاشتراك مدّد يدوياً في SQL Editor:

```sql
update shops set paid_until = now() + interval '1 month' where slug = 'dr-benali';
```

## بنية المشروع

```
db/migrations/001_init.sql   الجداول والقيود (تذكرة واحدة لكلّ هاتف يومياً…) و RLS
src/lib/domain/              منطق الطابور — دوالّ صافية بلا قاعدة بيانات (سهلة الاختبار)
  queue.ts                   التالي، الغياب، التأكيد، العتبات، الوقت المتوقَّع
  time.ts / phone.ts         توقيت الجزائر وساعات العمل / توحيد أرقام 05-06-07
src/lib/server/              الخادم
  service.ts                 حالات الاستخدام: أخذ رقم، التالي، وصلت… (معاملة مقفلة لكلّ تغيير)
  repo.ts / db.ts            SQL؛ pg للإنتاج و PGlite للتطوير والاختبار
  notify.ts / sms.ts         Web Push والرسائل
  auth.ts                    رمز السكرتيرة (scrypt) والجلسات الموقَّعة
src/lib/i18n.ts              كلّ النصوص بالعربية والفرنسية
src/app/                     الصفحات وواجهات API (Next.js App Router)
public/sw.js                 عامل الخدمة للتنبيهات
tests/                       اختبارات الوحدة والسيناريوهات
e2e/                         اختبارات المتصفّح (Playwright)
```

**كيف يعمل «التحديث الحيّ»:** الصفحات تسأل الخادم كلّ 4–10 ثوانٍ بطلب JSON صغير (أقلّ من 1 كيلوبايت)، وتتوقّف حين تكون الصفحة في الخلفية. اخترتُ هذا بدل اتّصال دائم لأنّه أصمد على شبكة 3G متقطّعة ولا يحتاج إعداداً إضافياً. يمكن لاحقاً إضافة Supabase Realtime فوقه.

## الخطوات التالية المقترحة
- العربون (القاعدة 7) لطبيب الأسنان والأخصّائي — يحتاج بوّابة دفع (CIB / الذهبية).
- الدفع الآلي للاشتراك.
- ربط بوّابة SMS جزائرية مباشرة بدل الوسيط.
- حدّ للطلبات حسب عنوان IP (حالياً: حسب الهاتف وحسب المحلّ).
- عدّة سكرتيرات/أطبّاء في نفس العيادة (عدّة طوابير).
